# 作品文件格式 v1 / v2

作品目录中的 `novelite.json` 是 UTF-8 JSON 清单，`chapters/<章节 ID>.md` 是 UTF-8 正文。新作品有一卷一章，可以继续创建卷章；新卷允许暂时为空，整个作品至少保留一章。章节操作保留既有身份。显示标题可以使用中文、重复或改名；它不参与磁盘路径。

清单包含整数 `version: 1`、作品 `id`、`title`、有序 `volumes` 数组。卷包含 `id`、`title`、有序 `chapters` 数组；章包含 `id`、`title`、`path`。全部身份为随机生成的 32 位小写十六进制字符串，在一个作品内唯一。正文路径必须准确对应 `chapters/<id>.md`，避免跨平台保留名、大小写及 Unicode 文件名碰撞。新正文换行是 LF，已有正文继续使用其换行风格。未知版本、未知清单字段、重复身份和越界路径被拒绝，不自动迁移或丢弃信息。

`.novelite.lock` 是持续保留的锁文件，操作系统锁随写实例或进程结束释放；文件存在不代表锁仍被占用。内部路径不接受符号链接或指向作品之外的目录。锁只约束遵守协议的客户端，不能阻止其他编辑器写入。正文和清单以长度与内容校验值识别外部变化；后台保存携带已知版本，在写入前再检查。检查与文件替换之间仍有外部软件抢写的窗口，不能等同于跨应用原子锁。

首次回收章或卷时升级到 v2。升级先将原 v1 清单原样保存在 `.novelite-v1-backup.json`，正文路径和内容保持原样；备份路径被不同内容占用时停止并报错。v2 增加可选 `recycle_bin` 数组，记录独立 `id`、删除范围 `title` 和有序 `chapters`。回收正文仍保留在原 ID 路径，恢复会把它们放进指定卷，保留章节 ID。整卷恢复将其中的章节放入目标卷；空卷记录没有正文。删除所有在用章节时建立新的空白章。旧版客户端拒绝 v2；不要将备份清单直接覆盖到仍在运行的作品上。

保存先将新清单和本次涉及的正文写入 `.novelite-journal.json`，再替换正文、清单，最后移除日志。新章正文以不可覆盖方式创建；中断重放遇到已完成的同内容文件可以继续，不同内容则报冲突。各文件使用同目录临时写入、文件刷新和替换；Unix 额外刷新父目录。重开时持有写锁的实例重放未完成日志，恢复完整新状态；也能读取早期单章日志。临时文件在日志发布前中断不属于已提交内容。不要删除尚待恢复的日志；备份应包含它。未知更高版本的清单禁止恢复覆盖。

这个日志保护事务一致性，不是历史快照，也不保证强制退出绝对不丢字。进程被终止后，最后持久化之后的输入可能丢失；磁盘故障或保存失败时损失窗口可能增长。系统断电和各类网络文件系统的持久性不等同于本机进程中断测试。

新恢复日志包含正文和清单的预期内容指纹。重放只接受旧版本或本事务已完成的新版本，第三种外部内容会阻止继续覆盖。冲突处理将双方可读取内容保存到 `conflicts/<ID>/`；放弃未完成事务前保留 `abandoned-journal.json`。这些副本不自动清理，随作品另存；它们不是新的在用章节映射。

重开遇到冲突日志时，从已验证日志恢复本地候选并进入冲突处理，不自动覆盖磁盘；最近章节位置不会替换恢复候选。清单损坏时仍可另存日志中的本地稿，原清单与日志保留；明确覆盖操作继续拒绝损坏或更高版本清单。

界面键位配置独立存放，不写入作品清单。当前桌面版尚未接入此格式；跨客户端互通另行实现。

`history/<章节ID>/<快照ID>.json` 独立保存历史，每个记录包含版本、章节身份、快照身份、创建 Unix 秒、递增序号、手动标记、正文及 FNV-1a 64 位文本校验值。校验用于发现意外损坏，不是安全签名。记录逐个原子发布，成功后再清理过期自动点；没有清单更新中断造成的悬空索引。`history-policy.json` 保存 `recent`、`days`、`max_bytes`，容量按每章保留记录的序列化大小计算，实际磁盘剩余不足仍可能导致写入失败。快照生成与清理在后台串行执行，切章、关闭和恢复会等待必要的恢复点持久化。

章节可带 `plan: { "outline": "多行梗概", "target_words": 3000 }`，作品可带 `target_words: 100000`；空计划和未设置目标省略。正文文件保持原样。复制章节保留计划，移动、回收、恢复和作品另存保留元数据。当前读取器接受未含这些可选字段的旧清单；尚不认识这些字段的旧客户端会拒绝打开含计划的清单，不应手工移除字段绕过检查。当前历史快照保存正文，大纲和目标随作品清单备份。
