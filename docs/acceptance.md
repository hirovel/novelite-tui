# 性能与体验验收

以下数值是首轮工程目标，尚无实现或测量结果。基准建议为 Apple Silicon M1、8 GB、macOS 上的本机 kitty；正式报告必须记录实际硬件、系统、kitty 版本、字体、窗口大小、构建提交与编译模式。

## 性能预算

| 项目 | 初始目标 | 测量边界 |
| --- | --- | --- |
| 输入响应 | p95 ≤ 16ms，p99 ≤ 33ms | 应用收到已提交字符事件到写完对应终端输出；不包含 IME 候选时间和屏幕扫描 |
| 交互帧 | p95 ≤ 16ms | 滚动、选区和布局切换的排版、绘制与输出总耗时 |
| 温启动 | ≤ 500ms | 启动进程到恢复上次章节的首个可编辑帧；冷启动另列 |
| 章节切换 | 热缓存 ≤ 100ms；冷读取 ≤ 300ms | 5 万字章节到可编辑帧 |
| 空闲 CPU | 平均 < 1% 单核 | 空闲 60 秒，无周期性全屏重绘；应用与 kitty 分别记录 |
| 应用内存 | 稳态 RSS ≤ 150 MiB | 百万字作品、10 万字活动章节、固定 10 MiB 编辑历史负载；峰值另列 |
| 普通自动保存 | p95 ≤ 200ms | 5 万字章节在本地 APFS 上后台写入并完成持久化；输入不中断 |

跨硬件结果不可直接判作相同门槛。初始数字未达标时定位瓶颈并记录取舍，不通过改变统计口径掩盖问题。终端渲染最终可见延迟用真实屏幕观察/录像补充，应用内部计时不能证明端到端延迟。

## 数据与执行方法

使用可重新生成的虚构语料，覆盖 1 万、10 万和 100 万字作品。包含 2 万汉字无硬换行段落、中文标点、ASCII、emoji ZWJ 序列、组合字符、制表符、空行、CRLF 和 Unicode 文件名。

Release 构建，在 80×24、120×40、160×50 三个窗口尺寸执行固定操作序列。每个响应测试预热后采集至少 1,000 次事件，报告 p50/p95/p99/max；启动测试区分冷/温并各重复至少 10 次。记录原始数据、峰值 RSS、CPU、帧数和终端输出字节量。

输入、滚动、保存、搜索分别测量，再测“输入期间全书检索与自动保存”组合负载。搜索必须可取消，结果不得阻塞输入或覆盖新修订。

## 编辑正确性

- macOS 系统拼音输入长句、候选切换、回车提交、Esc 取消；候选框位置正确，无重复输入、漏字或误执行命令。
- 中文与 emoji 混排后的横向移动、退格、跨行选择、鼠标定位始终停在字素边界；软换行不写进文件。
- 缩放窗口、折叠侧栏、切换布局后保持文字锚点；鼠标坐标与可见文本一致。
- 一次长粘贴作为合理的撤销事务；撤销/重做后正文与选区符合预期。剪贴板中的换行与特殊字符不会被当作控制命令。
- kitty 默认配置和应用专用配置分别验证快捷键；Cmd/Option 冲突有明确处理。不能以合成按键测试替代真实输入法测试。
- macOS Kitty 实机是通过条件；Windows 或 headless CI 只能补充验证。

## 模块化体验

- 三种布局共享文稿修订和历史；关闭/重开模块不丢失状态，不重复订阅事件。
- 所有命令可以从命令面板发现；隐藏模块不会留下不可见的键盘焦点。
- 搜索结果跳转、关闭覆盖层、恢复专注模式都有确定的焦点去向。
- 深色与浅色、窄窗与宽窗均检查；无需特殊字体即可识别所有关键操作。
- 长章节名、大字宽字符、无结果、保存失败、只读目录、首次空作品均有可读的布局。

## 持久化与恢复

- 保存后立即正常退出重开，最后输入、顺序、活动章节、大纲准确。
- 在临时文件写入、刷新、替换和结构事务中断点终止进程，重开得到完整旧修订或完整新修订，不能得到截断文稿或悬空章节映射。
- 模拟磁盘满、权限错误、外部改动、重复启动。错误状态不能显示已保存；恢复副本可以导出。
- 旧保存晚于新输入完成时，只更新其对应修订的持久化状态。
- 强制终止时用外部预期文本校验恢复结果，并记录最后持久化修订后的丢失窗口。
- schema 迁移前有备份；更新失败可继续使用原始数据。旧版打开新版 schema 时不能破坏文件。

## 验收证据

每个里程碑附构建提交、测试命令、环境、结果和未通过项。性能未测前不在 README 或发行说明宣称低延迟、低内存或“全部通过”。首个 Homebrew 发行必须验证干净安装、启动、旧版到新版升级及手稿保留。
