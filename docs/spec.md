# Novelite TUI 设计规格

日期：2026-10-17。产品范围和工作区会话测试入口已确认。实现与性能验证尚未开始。本规格取代初版 kitty 专用方案；详细交互与验收文档是本规格的补充。

## Problem Statement

作者希望直接在终端中写作，保留 Novelite 正式版的章节组织、编辑辅助和模块化界面，同时获得准确的中文输入、流畅的长文编辑和可靠保存。应用不能依赖某一种终端才能完成核心操作，也不能要求用户先修改终端配置。

首个使用场景是 macOS 上的 kitty，设计覆盖 macOS、Windows、Linux 的现代交互终端。鼠标点击、拖选和常规复制粘贴是主要体验。本阶段只安排本地测试，未实测的终端和平台不能标为已验证。

## Solution

提供独立的 Novelite TUI，默认正文优先，章节、大纲、搜索按需展开，可以固定并记住布局。阅读感、跟随终端、紧凑工作台三种视觉风格可选，首次默认阅读感。常规滚动默认，打字机模式和专注效果按需启用。

功能尽量对齐桌面版 v1.0.4，包括可编辑双分屏、中文排版、搜索替换、历史恢复、自定义快捷键和作品管理；独立随手记不在范围内。所有操作都有可发现的命令入口，颜色、鼠标、系统剪贴板与增强按键按终端能力启用。

作品保存为可携带的本地文件夹，自动保存和历史快照保护文本，外部修改有冲突时保留双方。未来 TUI 与桌面版使用同一格式、交替编辑；现有桌面版的格式适配另行实现，首版正文迁移使用已有导入导出。

## User Stories

1. 作为作者，我希望在现代终端默认配置下启动应用，以便直接写作。
2. 作为作者，我希望恢复上次作品、章节和位置，以便继续思路。
3. 作为作者，我希望正文默认占据主要空间，以便专注创作。
4. 作为作者，我希望按需展开并固定辅助模块，以便形成个人布局。
5. 作为作者，我希望选择三种视觉风格，以便适应不同环境。
6. 作为作者，我希望窗口变小时仍能编辑和保存，以便调整窗口布局。
7. 作为作者，我希望直接输入、用方向键移动和 Shift 选区，以便沿用常规编辑习惯。
8. 作为中文作者，我希望输入法候选提交与取消准确，以便连续写作。
9. 作为作者，我希望中文、emoji 和组合字符不会被操作拆坏，以便保持内容完整。
10. 作为作者，我希望点击、拖选、滚轮准确，以便快速修改正文。
11. 作为作者，我希望使用系统复制粘贴，以便与其他应用交换文本。
12. 作为作者，我希望剪贴板失败时得到反馈和内部替代操作，以便继续编辑。
13. 作为作者，我希望粘贴内容不会被误当快捷命令，以便原样导入素材。
14. 作为作者，我希望从命令面板找到操作并自定义键位，以便适应不同终端。
15. 作为作者，我希望快捷键被终端截获时有备用入口，以便无需改配置。
16. 作为作者，我希望软换行不修改实际段落，以便保留文件内容。
17. 作为作者，我希望切换常规滚动与打字机模式，以便兼顾修订与续写。
18. 作为作者，我希望段落聚焦和对话高亮可选，以便突出关注内容。
19. 作为作者，我希望撤销重做覆盖输入、粘贴和排版，以便放心修改。
20. 作为作者，我希望轻量输入辅助可关闭，以便保留输入习惯。
21. 作为作者，我希望手动执行整章排版且一次撤销，以便控制格式变化。
22. 作为作者，我希望管理多个作品和卷章，以便组织创作。
23. 作为作者，我希望创建、重命名、复制、排序和跨卷移动章节，以便调整结构。
24. 作为作者，我希望从回收区恢复章节，以便纠正误删。
25. 作为作者，我希望维护章节大纲和目标，以便规划情节。
26. 作为作者，我希望按标题或前后顺序跳章，以便浏览全书。
27. 作为作者，我希望章节查找替换与全书搜索，以便修改措辞和查阅前文。
28. 作为作者，我希望搜索结果带上下文且定位准确，以便判断匹配。
29. 作为作者，我希望左右或上下分屏都能编辑，以便对照修订。
30. 作为作者，我希望同章双窗格共享修改，以便避免互相覆盖。
31. 作为作者，我希望查看本章、全书字数和目标，以便掌握进度。
32. 作为作者，我希望关闭模块不丢失文稿或历史，以便自由调整界面。
33. 作为作者，我希望自动保存并能立即手动保存，以便保护输入。
34. 作为作者，我希望保存状态反映最新修订，以便判断是否已落盘。
35. 作为作者，我希望历史快照跨会话保留，以便找回过去写法。
36. 作为作者，我希望写盘失败时保留内容并能另存，以便应对磁盘异常。
37. 作为作者，我希望无本地修改时自动载入外部变化，以便交替使用工具。
38. 作为作者，我希望双方都修改时保留两份并让我处理，以便避免覆盖。
39. 作为作者，我希望作品由普通文本和可携带元数据组成，以便长期备份。
40. 作为作者，我希望导入 TXT/Markdown 并预览卷章识别结果，以便迁入手稿。
41. 作为作者，我希望导出全书或章节并保留正文格式，以便投稿。
42. 作为作者，我希望未来与桌面版交替打开同一作品，以便自由选择环境。
43. 作为作者，我希望百万字作品、十万字章节和双窗格保持流畅，以便完成长篇。
44. 作为作者，我希望后台搜索、统计和保存不阻塞输入，以便保持思路。
45. 作为作者，我希望正常退出后终端恢复，以便继续其他工作。

## Implementation Decisions

### 技术与范围

产品行为以上述已确认范围为准。推荐 Rust、Ratatui、Crossterm；编辑控件经本地中文编辑与性能验证后锁定。具体时间间隔、布局断点和缓存预算是待验证工程起点，可以按证据调整。

独立仓库、二进制、版本和发行。架构覆盖三大系统，实际发行平台另定，不因兼容设计而自动新增 Linux 发行。桌面版发布和更新入口不受 TUI 发行影响。

### 模块及测试 seam

工作区会话是统一操作入口：打开作品、处理文本/语义命令/窗口变化/任务结果、观察可见状态与保存状态、关闭会话。鼠标、快捷键与命令面板调用相同命令语义。

| Module | Interface 的责任 | 隐藏的复杂性 |
| --- | --- | --- |
| 工作区会话 | 接收用户动作，返回工作区状态及任务 | 焦点、窗格、模块生命周期和任务交错 |
| 编辑文稿 | 编辑事务、撤销重做、可见文本 | 字素、缓冲、历史、位置映射 |
| 作品持久化 | 读取、提交修订、恢复、外部版本处理 | 队列、原子替换、锁、恢复日志 |
| 内置功能模块 | 声明贡献、处理命令、订阅与卸载 | 章节、搜索、排版、大纲、统计、历史、导入导出 |
| 终端适配 | 能力、输入、绘制、剪贴板反馈、恢复终端 | 协议与系统差异 |

主要测试 seam 位于工作区会话 Interface，用户已确认。终端和文件系统分别有真实及可控测试 Adapter。只在协议和持久化平台语义需要时增加较低层合同测试，不为每个内部函数制造测试接口。

宿主统一管理主题、布局、命令冲突、焦点和重绘。模块通过稳定 ID 声明命令、面板、状态或格式化贡献，不能直接替换权威正文、绕过保存层写盘或在渲染时阻塞。停用模块取消任务和订阅并移走焦点。输入、保存与恢复的必要能力始终可达。首版不加载第三方插件。

### 文稿、双窗格与编辑

同一章节仅一份权威文稿与修订序列。每个窗格独立保留光标、选区、滚动锚点。同章双窗格立即共享修改，编辑按会话顺序进入章节历史，并映射另一窗格的位置。撤销作用于活动章节最后一个事务，同章双窗格可能撤销另一窗格的最近修改，反馈必须明确目标章节。

切换焦点、主题、布局、关闭窗格不清空文稿或历史。双窗格默认关闭，左右/上下均可；空间不足时临时仅显示活动窗格，保留另一个窗格并提供切换入口。

编辑单位是字素，屏幕定位使用终端列宽。软换行后上下移动按视觉行保留期望列。Markdown 标记可见，高亮不修改正文。控制字符使用可见替代表示，不原样作为终端指令输出。

### 布局与输入

默认正文居中，辅助模块按需打开，可固定并记忆。三种视觉风格与布局分别配置。临时缩窗收起不覆盖用户偏好，弹层关闭返回来源焦点，来源消失时返回活动编辑窗格。

终端核心基线为 Unicode、光标定位、基本键盘和屏幕刷新。无交互终端时不进入全屏编辑。增强键盘、鼠标、颜色和剪贴板按能力启用；探测有超时，无响应不算支持。所有功能有命令入口与备用键，具体映射待本地验证，不要求全局修改终端配置。

应用选区和终端选区分开。本机系统剪贴板优先，失败时明确反馈，可使用应用内部剪贴板；不得假称已写入系统剪贴板。粘贴分隔可用时整批插入，不可用时保留普通文本输入与终端原生粘贴入口，但不保证整批撤销识别。

中文预编辑由系统/终端管理，应用只插入已提交文本，不根据物理键猜测中文。光标位置正确更新以支持候选定位。协议回复、字符、控制事件分流。正常退出、挂起恢复和可处理异常时恢复终端；强制终止无法保证清理，提供恢复说明。

### 排版与搜索

引号/括号等输入辅助可关闭；不自动整章重写。段落排版、标点修复、去缩进和中英文间距手动触发，每次作为可撤销事务作用于当前章节。导出不暗中执行格式化。

章节查找替换与全书搜索分开，结果含上下文、章节和修订。旧查询结果不得覆盖新查询；过期位置重新校验。整章替换可一次撤销，全书搜索可取消。本规格不增加全书批量替换要求。

### 文件格式与迁移

作品文件夹包含 UTF-8 TXT/Markdown 正文、带版本的清单和独立历史。清单保存作品/卷/章稳定 ID、相对路径、顺序、标题、大纲、目标和回收信息。界面状态与正文分离。文件名处理跨平台保留名、大小写和 Unicode 冲突；显示标题不以文件名作为身份。

导入路径不得越出作品根，符号链接与冲突文件不能导致外部内容被覆盖。新文件默认 LF，既有文稿保留原换行风格；非 UTF-8 导入先确认编码再转换，不覆盖源文件。改名、排序、移动、回收使用可恢复结构事务。移除最近作品与删除实际手稿是不同操作。

旧桌面版先通过 TXT/目录迁移正文，其导出不完整携带大纲和历史，必须说明迁移范围。完整互通等待桌面版接入同一格式。未来完整迁移不能因 TUI 没有随手记界面就静默删除原随手记，应原样保留或单独导出。未知更高格式版本禁止写入，迁移前备份。

### 保存、历史与冲突

工程起点：停顿 300ms 保存，持续输入每 2s 安排后台保存。手动保存和正常退出覆盖会话全部脏文稿及结构，不只保存当前窗格。退出写入失败则保留会话，提供重试、另存或明确放弃。

保存状态区分未修改、待保存、保存中、已保存、冲突、失败。完成旧修订只能推进持久化水位，不能将更新的输入标为已保存。后台写入顺序受控，合并未开始的过期保存；不能以合并为由丢弃恢复所需历史。

同目录临时写入、刷新、目标平台可靠替换，结构变更配合恢复日志。Windows 文件占用、Unix 目录刷新等由持久化 Adapter 处理。恢复必须得到完整旧状态或完整新状态。强制终止仍可能损失最后持久化后的输入，不能承诺绝对零丢字。

快照与逐次自动保存分开。初始建议：有变化时每 5 分钟、切章/关闭、格式化或恢复前建立快照；内容相同不重复。每章保留最近 50 个自动恢复点，并保留最近 7 天每天至少一个；手动标记的恢复点不自动清理。保留策略可配置，磁盘不足明确提示，容量经负载测试调整。

外部变化与已知内容指纹比较，自身写入不算冲突。无本地修改且外部格式有效时自动刷新，尽量保持光标并保留刷新前快照。有本地修改时暂停对应对象自动覆盖，保留双方，提供载入磁盘、保留本地副本或明确覆盖选择；执行选择前再次检查磁盘版本。外部章节删除同样作为可恢复状态处理。

作品级写锁约束遵守协议的客户端，第二实例可只读打开；未来桌面端需遵守同一锁。外部软件不受锁约束，仍需变更检查，不承诺任意编辑器同时写入安全。

### 性能

基线为百万字作品、十万字章节与两个可编辑窗格。按需加载章节，优先评估 Rope 文本缓冲，软换行缓存按可见段落和宽度失效。输入线程不整书扫描；字数增量更新，检索、快照和保存后台执行。

输入优先、滚动事件合并、任务有处理预算。渲染绘制完整可见帧，缓冲区 diff 减少输出；无事件时休眠。任务结果附修订或查询代次，丢弃过期结果。缓存/历史有预算，但不得丢弃未持久化文稿。具体性能数字属于待测预算。

## Testing Decisions

从已确认的工作区会话 seam 执行真实用户路径：打开作品、输入、执行命令、切换窗格，再检查可见状态及落盘结果。测试不依赖私有函数、特定 Rope 或编辑控件实现。

覆盖编辑、双窗格、排版、模块开关、焦点、搜索、外部冲突与保存恢复。可控 Adapter 提供能力缺失、延迟和失败；真实临时目录与子进程终止测试验证文件替换和恢复合同。不同 Adapter 不共享错误的内存状态作为预期结果。

桌面原有跨版本测试使用独立预期文本校验重启后的真实手稿，TUI 沿用这一原则。新仓库当前没有实现和测试结果；桌面测试通过不代表 TUI 通过。

真实本地终端验收覆盖输入法、鼠标、系统剪贴板、焦点和最终视觉。合成事件不能替代真实中文输入法，内部计时不能证明屏幕可见延迟。本阶段不安排远程或云端兼容矩阵。按本机可用环境执行，其他环境保持待验证。

## Out of Scope

- 独立随手记、首版人物/世界观资料库、第三方插件市场和运行时。
- Vim 模态交互、实时富文本 Markdown、自由拖拽停靠。
- 独立客户端实时协作与自动文本合并。
- GUI 级字体排版、动态背景与依赖专有终端协议的核心功能。
- 本规格阶段的应用实现、实际发行、远程测试和全终端通过声明。
- 桌面版新格式适配及全平台发行包，后续另行安排。

## Further Notes

用户已确认进入规格阶段。键位映射、编辑控件、缓存、布局断点和跨平台文件替换需要本地验证；工程参数可据证据调整，不能降低已确认的行为要求。

后续先验证高风险编辑行为，再拆成可执行任务。基础原型通过不等于首版完成，完整首版以功能对齐表与验收清单为准。
